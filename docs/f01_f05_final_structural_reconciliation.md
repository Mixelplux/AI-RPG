## Confirmed outstanding structural finding — SR-01

**Origin: Action & Resolution's gate continuation/checkpoint supplier. Severity:
moderate, acceptance-blocking for this bounded integration.** Not state corruption,
not an F01 realization failure, and not an unmet general-language capability.

Deterministic reproduction from a fresh default session:

1. `repair the hinge` → committed repair; elapsed minute 10, one pin remaining,
   secured hinge, timber uncommitted, F05 returns `control/player_choice`.
2. `continue repair with timber without further damage` → recognized `resume`,
   method `repair`, constraint `no_damage`.
3. Actual: F05 eventually returns `complete/concluded/reuse`; timber is committed,
   elapsed time becomes 35, repair completes and cart passes.

The identical recognized restriction on a fresh repair returns
`control/authorization_constraint` with no cost. The gate's initial attempt passes
`conflicting_constraints=("no_damage",)` to its existing F05 policy; the resume
branch passes current constraints and missing timber, but omits that conflict.
The unchanged accepted policy returns `control/authorization_constraint` when
given the resumed authorization with the same conflict. The defect is missing
checkpoint information, not a failure of the pure F05 decision function.

Full trace: player supplies a recognized condition → interpreter retains it →
resume execution fails to supply the existing restriction conflict → authority
commits timber and 25 more minutes → context accurately records the condition
alongside executed completion. **No generated response was requested** for this
trace, and none is needed to locate the defect. A later faithful narration would
express an already incorrect authorization decision.

This finding does not assert that additional hinge damage actually occurred: the
fixture records no such new damage. The demonstrated issue is bypassing a condition
the scenario already treats as conflicting before an irreversible timber/time
commitment. State remains internally consistent and earlier pin/work remain, but
the player loses the opportunity to resolve that restriction before continuation.
The disposable session limits recovery cost; it does not remove the authorization
gap. No broader physics or damage-adjudication requirement follows.

Required bounded follow-up: reconcile the existing restriction check at the
resumption checkpoint; ensure a conflict retains control before timber/time
expenditure; preserve ten minutes, one committed pin, secured hinge and accepted
resolution. Add a focused offline regression contrasting restricted resumption
with later unrestricted explicit timber authorization and repeated completion.
Do not add new semantics for damage, general constraints or alternative methods.
This final review does not implement that follow-up.
