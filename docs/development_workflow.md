# Development Workflow

`WORKFLOW.md` is the authoritative development-governance document.

Development proceeds through owner-approved capability packages: coherent, bounded objectives that may contain several related internal milestones while preserving exactly one active sprint, manifest agreement, verification, atomicity, persistence safety, and explicit stop conditions. The lead agent may progress through routine in-scope milestones without repeated owner interruption. Owner approval and full review are reserved for meaningful product, scope, persistence, player-visible, and architecture decisions.

Completion reporting begins with the owner-level outcome; technical evidence is retained for a package boundary, material decision, blocker, access boundary, or explicit request. Review fatigue is a governance risk, so repeated low-value packets and approvals are not required.
